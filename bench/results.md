# Large-file benchmark

Generated by `npm run bench` on 2026-10-13. MuPDF 1.28.1. Node v22.14.0. Intel(R) Xeon(R) Processor, 4 cores, 16003.3 MB RAM.

Viewport is 1100×800 CSS pixels at fit-width (zoom rounded to 2 decimals, same rule as the viewer). Before is a full-page raster at that zoom, which is what the viewer used to request. After is the visible 1100×800 tile grid (512 device pixels) plus a display-list cache. Each column is its own process.

Fixtures (not committed): a 300-page letter spec book (1.7 MB, built in 31 ms) and a 200-sheet 24×36 drawing set (9.1 MB, built in 98 ms, 672 window modules per sheet). Open includes reading the file, enabling the undo journal, reading every page size, and classifying text on every page. Search is a case-insensitive scan of every page (`concrete` in the spec, `SHEET` in the drawings).

## What these numbers show

Text classification dominated open: on these files it was nearly the whole open time, and the content-stream sniff removes that scan. First paint at fit-width barely changes, because a letter page and a fit-width sheet are only a little taller than the 800 px viewport, so the visible tiles cover most of the pixels a full-page raster would draw. The 2× zoom re-render is where tiles win: the page has about four times as many pixels and the screen does not, and the display list from the first paint is reused. Scroll throughput improves more modestly for the same reason. Search and save still walk the whole file on one thread. Save of these freshly built files is already a few milliseconds; the before/after gap there is noise, not a different save path.

## Bottlenecks

- **Full-page raster at the current zoom.** Fit-width of a 24×36 sheet is still about 1106×1659 pixels, and zooming in rasterizes the whole sheet again. The screen only shows 1100×800. Tile rendering draws that rectangle (and reuses the display list when the zoom changes).
- **Text classification on open.** The old check ran MuPDF structured-text extraction on every page before the first paint, including pages that already have a normal content stream. The open path now treats a `Tj`/`TJ` in the page or a form XObject as text and only falls back to a full extract for scans and odd files.
- **One document, one thread.** Rendering, search, and save all run on the server's single MuPDF document and block the event loop. Search still walks every page from scratch; a second search is not cached. Save rewrites the file (`garbage`) so unused objects from edits are dropped.
- **Thumbnail rail.** Page thumbnails are requested only when they scroll into view, instead of for every page at once.

## What the after column changes

- The viewer paints fixed tiles for the visible area (plus a one-tile margin) and keeps a small display-list and PNG cache keyed by the document revision.
- `pageTextKind` sniffs content streams before extracting structured text.
- Page and thumbnail pixmaps are destroyed after the PNG is copied out, so the full-page fallback does not wait on the garbage collector.
